# 보도자료 중복기사 검사기

같은 보도자료가 한 매체에서 두 번 나가는 것을 승인 전에 막는 도구.
제목이 다르고 문장을 절반 넘게 고쳐 써도, 금액·인원·면적 같은 사실이 남아 있으면 잡는다.

## 구성

| 파일 | 하는 일 |
|---|---|
| `config.json` | 매체별 설정. **새 매체는 여기만 고친다** |
| `collect.py` | 10분마다 기사를 모아 `docs/articles.json`에 저장 (최근 45일) |
| `docs/index.html` | 데스크용 검사 화면. 원고를 붙여넣으면 비교 |
| `tools/crosscheck.js` | 모은 기사를 전부 서로 대조하는 검수 도구 |
| `.github/workflows/collect.yml` | GitHub Actions 예약 실행 |

## 새 매체에 설치

- **AI에게 시킬 때**: `PROMPT.md` — 처음 보는 AI도 이 문서만 읽으면 같은 품질로 만든다
- **사람이 할 때**: `SETUP.md` — 설치 절차와 자주 막히는 곳

한 매체당 20~40분.

## 판정 기준

`docs/index.html` 맨 위에 있다.

- `HI = 50` — 같은 보도자료로 보고 경고
- `MID = 30` — 목록에 보여줌
- `PART = 60` — 일부 문단만 겹칠 때의 기준

실측: 많이 고쳐 쓴 원고 65점, 무관한 기사 15점 이하, 정기 시리즈 기사 60점대(오탐).

## 한계 — 고객에게 반드시 알릴 것

- 기사가 나간 뒤 검사 가능해지기까지 **15~25분**. 그 안에 벌어지는 동시 출고는 못 잡는다
- 정기 기획 시리즈는 틀이 같아 걸린다. 정상이다
- 원고는 브라우저 밖으로 나가지 않는다 (와이파이를 끄고 검사해도 동작)
